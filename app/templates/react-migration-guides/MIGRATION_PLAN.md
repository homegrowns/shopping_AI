# React 마이그레이션 실행 계획

## 1단계: 현황 조사

- 원본 HTML, CSS, JavaScript의 기능을 목록화한다.
- 현재 저장소의 `package.json`, 빌드 도구, 폴더 구조, lint 및 test 설정을 확인한다.
- `/products`와 `/search`가 서로 다른 base URL을 사용하는 이유를 설정 파일에서 확인한다.
- 실제 검색 응답 예시 또는 백엔드 스키마를 찾아 상품 필드를 확정한다.

완료 조건: 변경 전에 보존해야 할 동작과 API 계약이 정리되어 있다.

## 2단계: React 실행 환경 구성

- 기존 React 환경이 있으면 그대로 사용한다.
- 환경이 없다면 Vite 기반의 최소 React 앱을 구성한다.
- 기존 파비콘 `shopping_agent_icon.jpg`를 public asset으로 보존한다.
- API 주소가 환경별로 달라질 필요가 있으면 `VITE_API_BASE_URL` 도입을 검토한다.

완료 조건: 빈 React 화면이 개발 서버와 production build에서 정상 실행된다.

## 3단계: 정적 UI 이전

- 제목, 채팅 로그, 이미지 미리보기, composer를 JSX로 옮긴다.
- 기존 CSS를 별도 스타일 파일로 이동한다.
- ID 기반 스타일을 컴포넌트 class 중심으로 정리한다.
- 이 단계에서는 네트워크 호출보다 원본 화면 보존을 우선한다.

완료 조건: 원본과 동일한 기본 레이아웃이 표시된다.

## 4단계: 상태와 이벤트 이전

- 입력값과 선택 파일을 React state로 관리한다.
- 파일 선택·교체·삭제와 미리보기를 구현한다.
- Enter 전송과 Shift+Enter 줄바꿈을 구현한다.
- IME 조합 상태에서는 Enter 전송을 막는다.
- 메시지 배열을 기반으로 사용자·어시스턴트 메시지를 렌더링한다.
- 새 메시지가 추가되면 `ref`를 이용해 채팅 끝으로 스크롤한다.

완료 조건: 직접 DOM 조작 없이 로컬 UI 상호작용이 동작한다.

## 5단계: API 계층 이전

- presigned URL 요청, S3 PUT, 검색 요청을 API 모듈로 분리한다.
- 진행 문구를 단계별로 갱신한다.
- 성공, 빈 결과, HTTP 오류, 서버 오류를 각각 처리한다.
- 요청 중 전송 버튼을 비활성화하고 중복 요청을 방지한다.

완료 조건: 텍스트 전용 및 이미지 포함 검색 흐름이 원본과 동일하게 동작한다.

## 6단계: 안전성과 접근성 보완

- `innerHTML`과 인라인 이벤트가 남아 있지 않은지 확인한다.
- 상품 링크를 안전하게 연다.
- 이미지 `alt`, 버튼 레이블, focus 상태를 추가한다.
- Blob URL 해제와 unmount 정리를 검증한다.
- 결과 배열이나 선택 필드가 누락되어도 렌더 오류가 발생하지 않게 한다.

완료 조건: 주요 보안·접근성·자원 정리 항목을 충족한다.

## 7단계: 테스트 및 최종 검증

- 컴포넌트 및 상호작용 테스트를 추가한다.
- fetch를 mock하여 업로드와 검색 상태 전이를 확인한다.
- lint, test, build를 실행한다.
- 브라우저에서 모바일 및 데스크톱 레이아웃을 확인한다.
- `VERIFICATION_CHECKLIST.md`를 완료한다.

완료 조건: 검증 명령이 통과하고 기존 핵심 동작이 보존된다.
